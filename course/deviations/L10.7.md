## L10.7: the serve loop records metrics and spans

`L10.7` now `upgrades` `rust/crates/tl-serve/src/server.rs`, L10.5's v1
server (the B9-2 serve-loop wiring item, B92-08). Its version keeps one
`EngineMetrics` behind a mutex: `record_http` for every request on both
ports, `record_request` when a generation ends (early errors too, with the
error `code` as `error_type`), and `set_engine` from the step loop's
`EngineStats` (plus the speculative accept rate) before `/metrics` renders.
The engine thread stamps when it takes a request (`Ev::Admitted`) and when it
samples each token; at the end of a request the server builds
`request_spans`, writes one `log_line` inside the SERVER span to stderr, and
posts `otlp_json` off the request path when `OTEL_EXPORTER_OTLP_ENDPOINT` is
set. L10.5's hand-written per-request span and `metrics_text` are gone.

Two values the engine does not report per request are approximations:
`engine.queue` ends when the engine thread takes the request off the
admission queue (the scheduler's own wait is inside `engine.prefill`), and
`tl.engine.prefix_hit_tokens` is 0 (the hit ratio is the gauge);
`tl.engine.chunks` is the prompt length over `prefill_chunk`, rounded up.

Call sites: `L10.9` takes `server.rs` over next and keeps calling these
units; `obs.02`'s local tier runs the engine and scrapes the histograms and
log lines this serve loop produces, so `obs.02` lists `L10.7` in `deps`
(as `dep.00` does `L10.0`) instead of `reading` (B95-06). The earlier owner's
snapshot is `course/ref/history/L10.5/rust/crates/tl-serve/src/server.rs`.

# Deviations from DESIGN.md

Where the design was ambiguous or wrong, the build took the simplest option
consistent with it. One row per deviation; the id prefix names the work that
recorded it (`H` = B1 core harness, `R` = the rest of the B1 harness: milestone,
conform, drill, doctor, export, the CI recipe, `verify --e2e`; `C` = the B1
contracts).

| id | what | why |
|---|---|---|
| H01 | The heavy harness logic is the Python package `sscourse` in the uv project `course/harness/` (stdlib only at run time; pytest and numpy only in its dev group). `practice/bin/ss` dispatches to `uv run --project course/harness python -m sscourse`. Each verb is one module under `sscourse/commands/`, so other work adds a verb by adding a file. | The design names `course/harness` as `sscourse` (5.1, 5.2); stdlib only keeps the root `uv.lock` and every learner env untouched. |
| H02 | `course/contracts/VERSION` (the source) holds only `semver`. Vendoring (`ss course init`, `ss contracts sync`) writes the learner copy with `semver`, `sha`, and `content_hash` (sha256 over every vendored file except VERSION). | A commit cannot name its own sha. |
| H03 | The Python contract pre-check is an AST comparison (every def and class in the unit's `.pyi` exists with the same parameter names), not `mypy.stubtest`. Rust and Go pre-checks are the manifest checks of 2.15; compile errors from the farm build report as "does not compile". | `stubtest` needs mypy and an importable package in the learner env; the AST check catches the drift that matters (names and parameters) with no dependency. |
| H04 | Rust uses one copy farm per learner, `.ss/rust-farm/` (and one per verify run), not `.ss/overlay/<ID>/rust/`. | Cargo fingerprints path packages by path and mtime. Per-module farms over one shared `CARGO_TARGET_DIR` reused another farm's artifacts: `ss verify course` saw a stubbed `acc.rs` pass using the reference build. One farm whose files are rewritten only when their bytes change is both warm and correct. |
| H05 | The Python `subst/` directory holds file copies (reference, stub, or mutant text), not symlinks. | Stubs and mutants have no file to link to; one mechanism for all three. |
| H06 | Units outside the dependency closure: C objects and the Rust and Go farms always use the stub of the current reference, even when the learner has a file; Python uses the learner's file when present and a stub (after the learner path) otherwise. | An unrelated half-written C, Rust, or Go file must not fail a compiled check; Python imports lazily, and 5.4 puts the learner's `python/` on the path. |
| H07 | The Hypothesis profile `ss` is registered by `course/tests/conftest.py` (always loaded through `--confcutdir`), not by `--with $ROOT/course/harness` as a pytest plugin. | Keeps the harness out of every learner env; same effect. |
| H08 | C stubs call `tl_set_last_error(msg)`, a setter the 2.4 `tinyllm/abi.h` does not list. The fixture `abi.h` declares it, plus `tl_alloc`/`tl_free` as the allocator seams units use. The rt.01 reference must keep the error slot and its setter outside the markers. | 5.2 requires every C stub to set `tl_last_error`, which needs a writable seam that still works when `abi.c` itself is a stub. The real `tinyllm/abi.h` (rt.01 work) should add these three declarations. |
| H09 | A C stub returning a non-status, non-pointer, non-void type is `return (T){0};`, not `return 0;`. | `return 0;` does not compile for struct returns such as `tl_arena_mark`; a compound literal works for scalars and structs. |
| H10 | Stub bodies are indented like the body they replace (C markers often sit at column 0). Go stubs rewrite imports the stub no longer uses as `_` imports. | Readable stubs; Go rejects unused imports. |
| H11 | A unit with no function bodies (a crate root that only declares `mod`s) is glue: it needs no markers, and check 5 does not ask for them. | 2.15 makes crate roots units owned by their first module; requiring markers in a file with nothing to stub would be noise. |
| H12 | `ss start` also stubs the sibling units of a Go package (not only a Rust crate root's submodules), so `go build ./...` in the learner repo compiles. | Same reason 2.15 gives for crate roots. |
| H13 | A dependency with no units (a primer, a practice module) never blocks `ss check`; it is noted. | `--ref-deps` has nothing to substitute for it, so blocking would be unrecoverable. |
| H14 | `ss diff` before a pass refuses unless `--spoil`, which records the module as spoiled. | 5.3 says "(after passing)" but not what happens before. |
| H15 | Practice-kind modules are checked by an executable `course/tests/<ID>/check` run in the learner repo; its exit code is the verdict. | 6.4 names artifact checks but not their mechanism. |
